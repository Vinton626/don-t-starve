这份文件只给写内容和 AI 看，不参与游戏页面。真正生效的样式在 css/common-tags.css；度名清单在 js/foodfarm/common.js 的 FOOD_DEGREES。

与 skillrules 独立：紫色、绿色、粉色等可以和技能树标签同色，不要求区分。只需避开全局规则 commonrules.html 里的色（三维、潮湿、伤害、b、warn、keyboard、notice 等）。本文件内部：各「度」之间、以及度与肥料之间，仍要可区分。

烹饪度颜色

基础食物的 degrees 键与标签同名。数字仍放在 b 里，文字用对应度标签。完整清单仅以下这些，不要再加。

肉度 键 meat，#c2185b。

蔬菜度 键 veg，#7dce7a。不要写成 veggie（veggie 是食用类型「素食」）。

水果度 键 fruit，#ff9b9b。

鱼度 键 fish，#6d93ad。

蛋度 键 egg，#e8c4a8。

甜味剂度 键 sweetener，#ffb6c1。

怪物度 键 monster，#c084fc。

乳制品度 键 dairy，#cfc8b4。

冰度 键 ice，#8ec8f0。

不可食用度 键 inedible，#9a9a9a。

魔法度 键 magic，#9b6bff。

油脂度 键 fat，#e6b85c。

种子度 键 seed，#a3c96b。与食用类型 seeds 不同。

装饰度 键 decoration，#d4a0c8。

干货度 键 dried，#b08968。

预处理度 键 precook，#7eb8a8。

例如 1蔬菜度、1.5水果度。

肥料颜色（种植）

与沃姆伍德正文里粪肥 / 堆肥 / 催长剂同色。人物页继续可用原标签；种植 / farm 正文优先用语义标签。

粪肥 的颜色是 #d4925a，与 brown 相同。标签 <manure>，数据键 manure。沃姆伍德写法：<brown>粪肥</brown>。

堆肥 的颜色是 #c5c5c5，与 grey 相同。标签 <compost>，数据键 compost。沃姆伍德写法：<grey>堆肥</grey>。

催长剂 的颜色是 #b3e5ff，与 lightblue 相同。标签 <formula>，数据键 formula。沃姆伍德写法：<lightblue>催长剂</lightblue>。

种子 fertilizer 直接写每阶段三肥净值，键是 manure / compost / formula：负数=消耗，正数=产出，0 可省略或写 0。例如土豆：{"formula":-4,"compost":2,"manure":2}。

三肥圆圈 + 耗水/阶段

种植篇卡片与种子弹窗用四维圆圈：前三个是每阶段三肥净值（产出 − 消耗），第四个是耗水/阶段。悬停写「催长剂/阶段」「堆肥/阶段」「粪肥/阶段」。写法同 commonrules 的 state。

stat-formula 催长剂（🧪，底色 #3d7fa6）、stat-compost 堆肥（🍂，底色 #6e6e6e）、stat-manure 粪肥（💩，底色 #8a5a2e）。肥料数值放在 b 里，正数带 +，例如 +2、-4。

stat-water 耗水/阶段（💧，底色 #2a6f9e）。文案写「耗水/阶段」，不要写「潮湿值」。数据里写百分比数值（如 0.75 表示 0.75%），页面展示时加 %。例如 <notice text="耗水/阶段"><b>0.75%</b></notice>。

耗水/阶段不参与三肥配比运算，只在页面展示。

生成肥料圆：CommonTags.stateOrbHTML("formula", "<b>-4</b>")；水：CommonTags.stateOrbHTML("water", "…")。

食用类型（foodtype）

普通食物本体、烤 cooked、晾 dried、种子 seed、料理都可写，对应谁能吃。和烹饪「度」无关。不要再用 secondaryfoodtype。

写法：

只有一种：写 foodtype，例如 "foodtype":"veggie"。

多种：写 foodtype + foodtype2 + foodtype3… 有几种写几个。例如浆果 "foodtype":"veggie","foodtype2":"berry"；怪物肉 "foodtype":"meat","foodtype2":"monster"。

也可以从 foodtype1 起笔：必须同时有 foodtype2（只写 1 不合法）。之后同样 foodtype3…

完整键与中文（仅这些）：

veggie 素食、generic 通用、meat 肉、elemental 元素、gears 齿轮、horrible 可怕、insect 昆虫、seeds 种子、berry 浆果、raw 生的、burnt 烧焦的、nitre 硝石、roughage 粗食、wood 木制、goodies 好东西、monster 怪物、moonshard 月亮碎片、miasma 瘴气。

清单在 js/foodfarm/common.js 的 FOOD_TYPES。展示用 Foodfarm.foodTypeText(entry)。

保质期

普通食物、烤/晾、种子、料理都可写 spoilDays。数字是天数，详情显示为「保质期：N 天」。不会腐烂写 "spoilDays": "永久"，页面只显示「永久」，不加「天」。没有、或写 null，就省略这一行。

fallback：布尔。为 true 时这道是保底料理（原版潮湿黏糊 stickygoo）。满 4 格且没有任何其它料理匹配时，锅结果直接展示它的详情；不参与「可能产生」预览，避免每锅都挂着。判定时也不会和其它料理抢优先级。

requires 的 op：> / >= / = 按字面比较。写 <= 时判定为 0 < 该度 ≤ value（必须有一点、且不超过）；写 < 同理为 0 < 该度 < value。开区间如 1 < n < 2 写两条（数组是且）。某条也可以是 or，满足其中任一分支即可，例如水果 > 0 或蔬菜 ≥ 0.5：

"requires": [
  { "degree": "meat", "op": ">", "value": 1 },
  { "or": [
    { "degree": "fruit", "op": ">", "value": 0 },
    { "degree": "veg", "op": ">=", "value": 0.5 }
  ]}
]

开区间两条（数组是且）示例：

"requires": [
  { "degree": "meat", "op": ">", "value": 1 },
  { "degree": "meat", "op": "<", "value": 2 }
]

闭区间用 >= + <=。若只要「至多 N、可以为 0」，用 limit 禁止该度，或不要单独写带隐含下界的 < / <=。

料理的 cookSeconds、priority 还没定稿时写 "待补充"。详情只显示「待补充」：烹饪时间后面不加「秒」。判定时这个优先级按 0 和其他料理比较。must 的 op 按原样显示，"=" 表示该食材格数必须正好等于 value。must.name 前面可以写 <烤>、<晾>，对应这条食物的 cooked.id、dried.id。生的名字本身也算。只写 <烤>大肉 是生和烤两种；<烤><晾>大肉 是生、烤、晾三种。两种食材都能用时，把它们放进 or：{"or":[{"name":"黄油","op":">=","value":1},{"name":"蜂蜜","op":">=","value":1}]}，满足其中一条即可。若两项都允许烤、但不能全烤（鳄梨酱：仙人掌肉 + 石果），must 只写两条 <烤>…，再加碟级字段 "atLeastOneRaw": ["仙人掌肉","石果"]：名单里至少有一种是生的；这不是再占一格必用，其余两格仍可随便填。锅里有烤或晾的食物，格子右上角可以切换形态，晾在烤左边。沃利专属料理写字符串字段 "exclusive": "warly"。卡片详情提示「大厨特色菜，需要使用便携烹饪锅烹饪」；烹饪锅最终结果里出现这道菜时也显示这句。同一配方还匹配到任何其他料理（不论优先级高低）时，再加一句「普通烹饪锅只会做出其他料理」。

基础食物字段

fish：鱼类标识。写 true（或字符串 "fish"）时进入钓鱼指南。鱼类仍写在 basic_food.json 里。多数海鱼写 hide: true，普通食物图鉴不显示；池塘/苔藓池塘里的鱼可当普通食物写三维，不写 hide 就会出现在食物图鉴，也可同时出现在钓鱼指南。钓鱼指南不展示生命/饥饿/理智三维，只看区域、掉落、季节/活动与重量。

fishing：钓鱼信息对象，可选。常用键：

  • areas：区域数组。取值 pond 池塘、mossy_pond 苔藓池塘、shallow 浅海、ocean 中层海、deep 深海、dangerous 危险海域、waterlogged 水中木。不写或空数组时页面显示「不指定特殊区域」。
  • drops（也可写在条目顶层，见下）：掉落数组。鱼类仍可写在 fishing.drops。
  • seasons：出现季节数组，spring / summer / autumn / winter。不写或空数组视为四季，页面显示「四季」；只有少数鱼需要指定季节时才写。
  • events：活动名字符串数组，与季节一起显示在「出现」。
  • weight：{"min":最轻,"max":最重}。也可直接写 weightMin / weightMax。
  • note：补充说明，可选。

由海草产生的鱼：写在条目的 source（例如 "source": "海草"），不要塞进季节/活动。季节/活动只写真正的出现时段；source 表示从哪里产出。条目不必写 origin：归属由 mod_config.json 的路径与 tag 在加载时注入。

drops：通用掉落，写在条目顶层。普通食物（如鼹鼠）、鱼类、之后的怪物篇都用同一套。推荐数组；也可以写单个对象。每项可以是字符串，或 {"name":"小肉","chance":1} / {"name":"小肉","value":1,"chance":1} / {"id":"...","name":"...","chance":0.25}。value（或 count）是数量，写了就显示为 ×N（含 ×1）；不写则不缀数量；chance 为 0–1 时按百分比显示，大于 1 时当百分数，字符串原样显示。未写该字段：页面不显示掉落行；显式 "drops": null：显示「无掉落物」。鱼类若只写在 fishing.drops 里也认；新数据优先写顶层 drops。

effect：效果文案，基础食物与料理都可写。页面显示「效果：…」。冷食写 <冷食>，热食写 <热食>，后面接持续时间等（例如 "<冷食>持续5秒"）。展示时展开为：

  • 冷食：在角色个体温度高于12°时生效，降低个体体感温度40°，
  • 热食：在角色个体温度低于62°时生效，提升个体体感温度40°(提升效果会随新鲜度减少而减少)，

词条「冷食」「热食」带颜色（冷 #6ec8f0，热 #e4572e）。烤/晾子对象若未单独写 effect，不继承生的效果。

hide：布尔。为 true 时不出现在普通食物图鉴卡片里，但仍可作为料理篇锅原料（噩梦燃料、树枝这类非食用原料用它）。鱼类常用它从图鉴藏掉。默认 / 省略视为 false。

noCook：布尔。为 true 时不能放进烹饪锅（选择栏、补格、举例配方都不会用到）。与 hide 互不干涉：图鉴显隐只看 hide，入锅只看 noCook（以及下面的 plantOnly）。特殊内容既不是料理、又不能入锅时，仍写在基础食物里，标 noCook: true；需要从普通食物图鉴藏掉就再加 hide: true。默认 / 省略视为 false。

plantOnly：布尔。为 true 时只留种植记录，不进食物图鉴，也不进烹饪锅。针刺旋花用它，并同时写 hide: true。

cooked：烤熟形态子对象，可选。只有写了才参与切换。

dried：晾干形态子对象，可选（肉、海带等才有）。只有写了才参与切换；多数食物不必写这个字段。

图鉴卡片右上角按已有字段各放一个按钮，晾在烤左边。点「晾」或「烤」切到该形态，再点同一个按钮回到生。只有其中一个字段就只显示对应按钮。两个字段都没有则缩小显示 *，悬停提示「不可烤不可晾」。

烤/晾子对象常用字段：id / name / health / hunger / sanity / spoilDays / foodtype（及 foodtype2…）/ degrees。

种子字段

seed.foodtype（及 foodtype2…）：种子自身的食用类型，常见 seeds。写法同普通食物。

seed.spoilDays：种子保质期（天）。没有就省略。

seed.hate_season：不喜欢的季节数组，取值 spring / summer / autumn / winter。不在数组里的季节都算合适。没有就写 []。

seed.water：耗水/阶段，百分比数值（如 0.75 = 0.75%）。种植卡片第四维展示时带 %；不参与配比。没有可省略。

seed.desc：简短描述，可用正文标签；没有就写空字符串。

seed 可以写成完整对象，也可以写成另一条食物的 id，多种植株共用同一颗种子时用 id。例如必忘我和后面的杂草都写 "seed": "seeds"，种子本体只写一次，并带上它自己的 cooked、degrees。每株不一样的肥、水、季节不要写进种子，写在植株的 grow 里，种植篇会叠到这颗种子上。

原版作物种子烤熟后都是同一份烤种子：写与 seeds.cooked 相同的对象即可，id 为 seeds_cooked，名字「烤种子」。嵌在植株里的种子也会出现在普通食物图鉴，按名字或 id 搜索。同一种子只出现一张卡片。

料理详情里的配方举例

不枚举全部可行组合（组合数会爆炸）。详情底部「可实现举例」每次随机给出至多两条不同的 4 格配方。必用原料按名字放入；每种度要求在不触犯 limit 的食材里随机挑选，有纯单度食材时优先用纯单度。需求和必用都满足以后，剩下的空格从所有不在 limit 里的纯单度食材中再随机配。凑满后用烹饪判定校验，只有真正会做出这道菜的配方才展示。举例下面有「随机生成其他」，点一次会再随机两条，并避开当前正在显示的配方。烹饪锅里点「可能制作的料理」也是随机补空格：已有食材保留，必用和度要求在符合条件的食材里随机挑；这些都满足后，再随机选一种不在 limit 里、优先锅里还没有的度，把剩下的空格补上。料理数据不必再写 random。
